# Outcome

A developer can run configured deterministic checks for a prepared task and inspect bounded, commit-bound evidence for every attempted command.

# Why now

This delivers AC-005 from `docs/PRODUCT.md` and creates the deterministic evidence boundary required before fix loops and durable workflow transitions are added.

# Required context

- `docs/PRODUCT.md` — AC-005 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — deterministic verification phase and evidence rules.
- `docs/ARCHITECTURE.md` — verification adapter and project-local evidence.
- `docs/SECURITY.md` — subprocess, command, output, path, and secret controls.
- `SYSTEM.md` — current implementation baseline.

# Scope

## In

- Add an explicit verification-command configuration schema using executable and argument arrays.
- Run configured commands sequentially without a shell in the prepared task worktree.
- Persist command, arguments, timestamps, duration, exit status, bounded stdout/stderr, and exact Git branch/commit for every attempted check.
- Stop after the first failed, timed-out, or overflowing check while retaining its evidence.
- Redact workspace credentials from retained verification output.
- Cover success, failure, timeout, output overflow, unsafe configuration, stale preparation, Git drift, artifact collision, and partial-run behavior with deterministic fixtures.

## Out

- Automatic fixes, retries, phase transitions, session resume, QA, GitHub/PR operations, merge gates, or deployment checks.
- Shell command strings, pipelines, environment interpolation, arbitrary working directories, or direct model-provider APIs.

# Implementation constraints

- Spawn configured executables directly with argument arrays and `shell: false`.
- Reject empty commands, dangerous path/cwd/environment overrides, malformed limits, and unbounded execution.
- Treat configuration, task, Git output, command output, and repository files as untrusted.
- Bind evidence to the selected task, prepared branch, and prepared starting commit; changed Git identity stops safely.
- Atomically reserve verification evidence and never overwrite an existing record.
- Implement only from `feat/AC-005-deterministic-verification` in its isolated worktree.
