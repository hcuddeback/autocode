# Outcome

A workflow adapter can pace and retry durable phase effects with persisted attempt and elapsed-time budgets, minimum spacing, and bounded backoff so interruption or restart never resets a budget or shortens an outstanding wait.

## Why now

This delivers AC-011 from `docs/PRODUCT.md`, completing the MVP 1 durable workflow foundation after AC-010 established interruption-safe effect reconciliation.

## Required context

- `docs/PRODUCT.md` — AC-011 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — pacing, waits, recovery, and terminal-state rules.
- `docs/ARCHITECTURE.md` — versioned local state, event ordering, locking, and retry recovery.
- `docs/SECURITY.md` — untrusted adapter data, bounded execution, and effect reconciliation.
- `SYSTEM.md` — current durable-run baseline.

## Scope

### In

- Extend the reusable durable executor with a validated retry and pacing policy.
- Persist every started attempt, the original elapsed-time budget origin, and each next-eligible timestamp in the durable event log and snapshot.
- Enforce a finite per-phase attempt ceiling and a finite run elapsed-time ceiling across process restarts.
- Enforce minimum spacing between effect attempts and capped exponential backoff, honoring a bounded adapter-provided retry-after delay.
- Reconcile an interrupted in-flight effect before any retry and count every subsequent adapter invocation against the original persisted budget.
- Use injectable monotonic test controls around wall-clock timestamps and waits without trusting them as durable evidence.
- Add restart-focused tests proving attempts and outstanding backoff are not reset or shortened.
- Fail closed on corrupt policy/state, clock or wait failures, malformed retry results, exhausted budgets, and incompatible definition changes.

### Out

- End-to-end wiring of every existing workflow phase or provider adapter.
- Calendar-based quiet hours, cross-run scheduling, stop-after-current-task queues, fairness, or parallel execution.
- Automatic retry of an ambiguous side effect without reconciliation.
- Hosted scheduling, distributed locks, or background services.

## Implementation constraints

- Reuse AC-010's event-before-snapshot persistence, lock, path, credential, and reconciliation boundaries.
- Defaults remain bounded and preserve existing adapters that return `applied`.
- Retryable results assert that an effect was not applied; thrown or malformed callbacks remain ambiguous and require reconciliation on resume.
- Delay arithmetic and timestamps are finite, integer, capped, and safe for Node timers.
- Returned state and callback contexts remain deeply immutable and isolated from caller mutation.
- Implement only from `feat/AC-011-pacing-retry` in its isolated worktree.
