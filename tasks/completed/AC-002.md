# Outcome

A developer can ask AutoCode to select the first ready task from the repository queue. AutoCode validates the task catalog, selects only a task whose declared dependencies are complete, skips completed tasks, and explains when no task is selectable.

## Why now

This delivers AC-002 from `docs/PRODUCT.md` and is the intake foundation for the MVP workflow.

## Required context

- `docs/PRODUCT.md` — AC-002 and MVP boundaries.
- `docs/WORKFLOW.md` — intake and JIT task-selection rules.
- `docs/ARCHITECTURE.md` — local TypeScript CLI boundary.
- `docs/SECURITY.md` — untrusted repository content and path controls.
- `SYSTEM.md` — current implementation baseline.

## Scope

### In

- Load and strictly validate active and completed Markdown task records.
- Deterministically select the first `ready` task whose dependencies are `done`.
- Report dependency blockers when no ready task is selectable.
- Expose selection through the local CLI.

### Out

- JIT task refinement, implementation planning, run persistence, phase orchestration, and Codex sessions.
- Mutating task status during selection.
- Hosted services or parallel task execution.

## Implementation constraints

- Treat task files as untrusted and reject malformed, duplicate, oversized, or unsafe task identities.
- Do not follow symbolic-link task files.
- Preserve the documented local-first architecture and single-task WIP limit.
- Implement only from `feat/AC-002-task-selection` in its isolated worktree.

- [x] A ready task with completed dependencies is selected deterministically.
- [x] Ready tasks with missing or incomplete dependencies are not selected and have clear reasons.
- [x] Completed tasks are skipped.
- [x] Malformed task catalogs fail safely.
