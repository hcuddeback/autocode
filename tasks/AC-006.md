# Outcome

A workflow adapter can apply a configured, finite fix loop and receive an explicit successful, blocked, or failed outcome with transition evidence for every attempt.

# Why now

This delivers AC-006 from `docs/PRODUCT.md` after deterministic verification and establishes the bounded transition policy needed before QA and durable resume are added.

# Required context

- `docs/PRODUCT.md` — AC-006 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — fix/reverify rules and terminal outcomes.
- `docs/ARCHITECTURE.md` — failure policy and state boundaries.
- `docs/SECURITY.md` — untrusted results and bounded execution.
- `SYSTEM.md` — current implementation baseline.

# Scope

## In

- Add validated fix-loop configuration with a finite attempt ceiling.
- Add a reusable fix-loop runner that records deterministic state transitions.
- Stop successfully when verification passes, block immediately on a non-retryable condition, and fail when the configured attempt ceiling is exhausted.
- Reject malformed callback results and callback failures without treating them as success.
- Cover zero-fix success, eventual success, blocked outcomes, exhaustion, invalid configuration/results, and callback failures with transition tests.

## Out

- Durable pause/resume state, persisted pacing/backoff, QA, PR review, merge/deployment gates, or multi-task orchestration.
- Parsing free-form Codex review prose or automatically choosing a fix from untrusted model output.
- Changing the AC-004 session artifact layout or overwriting AC-005 verification evidence.

# Implementation constraints

- The configured ceiling counts fix attempts, not the initial check.
- Every attempted check and fix produces an ordered transition record with a human-readable reason.
- Callback exceptions and malformed results fail closed with an explicit `failed` outcome.
- The runner must never exceed the configured ceiling or retry a blocking result.
- Implement only from `feat/AC-006-bounded-fix-loops` in its isolated worktree.
