# Outcome

A workflow adapter can execute a bounded ordered run through durable checkpoints, pause at a safe boundary, and resume after interruption without repeating a completed external side effect.

## Why now

This delivers AC-010 from `docs/PRODUCT.md` and the MVP milestone's required forced-interruption evidence after the completion-gate policy introduced by AC-009.

## Required context

- `docs/PRODUCT.md` — AC-010 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — checkpoint, resume, reconciliation, and terminal-state rules.
- `docs/ARCHITECTURE.md` — versioned local state, atomic snapshots, event ordering, locking, and recovery.
- `docs/SECURITY.md` — path constraints, untrusted adapter data, and effect reconciliation.
- `SYSTEM.md` — current implementation baseline.

## Scope

### In

- Add a reusable durable executor for one ordered run with bounded uniquely identified phases.
- Persist a versioned run snapshot atomically and append a durable event before replacing the current snapshot.
- Persist a stable effect identity before invoking each phase adapter.
- Support deliberate pause only at safe phase boundaries.
- On resume, acquire the run lock, validate stored state, and reconcile an ambiguous in-flight effect before deciding whether to complete it, execute it, or block.
- Add a forced-interruption integration test that applies an effect, terminates before completion is checkpointed, and proves resume reconciles without applying it again.
- Fail closed on corrupt state, incompatible definitions, unsafe paths, concurrent ownership, ambiguous reconciliation, and malformed adapter results.

### Out

- Wiring every existing workflow policy module into one end-to-end product command.
- GitHub, deployment, browser, Codex, or other provider-specific effects.
- Pacing, cooldown, retry-budget, quiet-hours, or polling policy from AC-011.
- Parallel runs, distributed locks, hosted state, or exactly-once guarantees from providers that cannot reconcile an idempotency identity.

## Implementation constraints

- State stays under the selected project worktree's gitignored `.autocode/runs/` directory.
- Phase and run identifiers are bounded safe path segments; definitions and adapter results are untrusted and copied before use.
- Each effect transition is recorded durably before adapter invocation; resume never blindly retries an in-flight effect.
- Reconciliation may report applied, not applied, or ambiguous; ambiguous state blocks without invoking the effect.
- Snapshots use write-then-rename publication and event records precede the snapshot they describe.
- Returned state is deeply immutable and isolated from caller mutation.
- Implement only from `feat/AC-010-pause-resume` in its isolated worktree.

## Done when

- [ ] A new run executes ordered phases once and retains versioned snapshots plus ordered transition events.
- [ ] A requested pause stops at a safe boundary and a later invocation resumes from the first incomplete phase.
- [ ] Forced interruption after an effect but before its completion checkpoint is reconciled on resume without repeating the effect.
- [ ] Not-applied reconciliation executes the original stable effect identity, while ambiguous reconciliation blocks safely.
- [ ] Corrupt, stale, conflicting, concurrent, excessive, accessor-backed, and proxy-backed inputs fail closed.
- [ ] Documentation and `SYSTEM.md` match behavior.
