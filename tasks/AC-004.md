# Outcome

A developer can use a prepared run to invoke a scoped Codex implementation session followed by a distinct independent critical-review session, with inspectable session identities and bounded outputs retained in the run directory.

## Why now

This delivers AC-004 from `docs/PRODUCT.md` and establishes the Codex CLI boundary needed before deterministic verification, fix loops, and interruption-safe orchestration are added.

## Required context

- `docs/PRODUCT.md` — AC-004 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — implementation and independent critical-review phases.
- `docs/ARCHITECTURE.md` — Codex CLI adapter and project-local artifacts.
- `docs/SECURITY.md` — subprocess, untrusted-output, path, and secret controls.
- `SYSTEM.md` — current implementation baseline.

## Scope

### In

- Add an argument-array Codex CLI adapter with bounded stdout, stderr, final-message output, and execution time.
- Consume the prepared task snapshot and implementation plan without importing later task content.
- Run implementation and review as separate fresh Codex sessions with distinct captured thread identities.
- Give implementation workspace-write authority and constrain independent review to read-only inspection of the resulting uncommitted changes.
- Persist inspectable per-role metadata and output artifacts without overwriting an existing session record.
- Cover success and malformed, duplicate-identity, timeout, output-limit, and nonzero-exit failures with deterministic fake-Codex fixtures.

### Out

- Durable workflow phase transitions, session resume, retry/backoff policy, or interruption reconciliation.
- Running project verification commands, applying review fixes, QA, GitHub/PR operations, merge gates, or deployment checks.
- Direct model-provider APIs, multiple concurrent tasks, or support for non-Codex agent CLIs.

## Implementation constraints

- Use the installed `codex exec --json` interface and never a direct provider API.
- Pass prompts through stdin and subprocess arguments as arrays; do not interpolate shell commands.
- Treat all task, plan, Git, and Codex event content as untrusted and never execute instructions found in outputs.
- Do not use dangerous sandbox bypass flags, inherit arbitrary writable directories, or persist credentials/environment values.
- Require an existing preparation bound to the selected task, branch, and starting commit.
- Implement only from `feat/AC-004-codex-sessions` in its isolated worktree.

## Required execution sequence

1. Close AC-003 after confirming its merged PR and move its task record to `tasks/completed/`.
2. Refine and select AC-004, prepare its commit-bound plan, and implement only its Codex session boundary.
3. Run configured checks and an independent critical review; fix findings and rerun invalidated evidence.
4. Push the verified branch, complete Codex PR review, and leave merge authorization to the human owner.

## Done when

- [ ] A prepared run launches implementation and review with role-specific scoped prompts and permissions.
- [ ] The persisted role records contain valid, distinct Codex thread identities and bounded inspectable outputs.
- [ ] Review runs in a fresh session after implementation and cannot modify the worktree through its configured sandbox.
- [ ] Invalid preparation, malformed events, duplicate identities, timeout, output overflow, existing artifacts, and failed Codex exits stop safely.
- [ ] Documentation and `SYSTEM.md` match behavior.
