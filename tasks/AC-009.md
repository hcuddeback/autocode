# Outcome

A workflow adapter can evaluate configured merge and production evidence and receives immutable structured evidence that permits completion only when every required signal exists, passed, and is bound to the current subject identity.

## Why now

This delivers AC-009 from `docs/PRODUCT.md` after Codex PR-review disposition and establishes the final policy boundary before durable pause/resume orchestration.

## Required context

- `docs/PRODUCT.md` — AC-009 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — merge, production-applicability, production-verification, freshness, and completion rules.
- `docs/ARCHITECTURE.md` — policy/gate, evidence, adapter, and local-first boundaries.
- `docs/SECURITY.md` — untrusted external evidence and authority boundaries.
- `docs/RELEASE.md` — production identity, verification, and rollback expectations.
- `SYSTEM.md` — current implementation baseline.

## Scope

### In

- Add a reusable completion-gate evaluator for bounded configured merge requirements and observed signals.
- Bind merge signals to the exact expected head commit so stale evidence cannot pass.
- Require an explicit production required or not-applicable decision with a substantive reason.
- When production applies, bind every required production signal to the exact deployment and source commit.
- Return deeply immutable structured evidence for every configured gate and an overall passed, blocked, or failed outcome.
- Fail closed on malformed, duplicate, unexpected, missing, pending, stale, or failed evidence and cover behavior deterministically.

### Out

- GitHub, CI, deployment, browser, or provider API polling and authentication.
- Performing merges, deployments, rollbacks, approvals, or any other external side effect.
- Durable run-state integration, automatic retries, pacing, and pause/resume orchestration.
- Time-based freshness policy; freshness in this task is exact immutable subject identity.

## Implementation constraints

- Gate configuration and observed signals are untrusted data and must be copied, validated, bounded, and never treated as authority beyond the configured gate.
- Each phase must configure one through 64 uniquely identified gates and supply at most one observed signal per gate.
- Merge evidence is current only for the expected head commit; required production evidence is current only for the expected deployment and its source commit.
- Missing, pending, or stale evidence blocks; an explicitly failed signal fails; invalid input fails closed by throwing before partial evidence is returned.
- A production not-applicable decision requires a substantive bounded reason and cannot include deployment evidence.
- Returned requirements, evaluations, and phase evidence are deeply immutable.
- Implement only from `feat/AC-009-merge-production-gates` in its isolated worktree.
