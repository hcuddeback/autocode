# Outcome

A developer can prepare the selected task for implementation. AutoCode validates that the task is an executable contract and creates an idempotent, inspectable plan artifact bound to the selected task and current Git commit.

## Why now

This delivers AC-003 from `docs/PRODUCT.md` and provides the scoped input required before role-separated Codex sessions can be introduced by AC-004.

## Required context

- `docs/PRODUCT.md` — AC-003 acceptance and MVP boundaries.
- `docs/WORKFLOW.md` — JIT refinement and implementation-plan phases.
- `docs/ARCHITECTURE.md` — project-local state and evidence binding.
- `docs/SECURITY.md` — untrusted input, path, and command controls.
- `SYSTEM.md` — current implementation baseline.

## Scope

### In

- Validate required task-contract sections and reject template placeholders.
- Require exactly one dependency-ready selected task and a non-`main` Git worktree.
- Create a task snapshot and editable implementation-plan artifact under `.autocode/runs/`.
- Bind planning metadata to the exact task digest, task path, branch, and current commit.
- Make repeated preparation at the same task/commit idempotent and fail safely on conflicting artifacts.

### Out

- Invoking Codex CLI, generating plan prose with a model, executing implementation, or advancing workflow phases.
- Refining later queue items or importing their content into the selected task context.
- Worktree creation, durable phase orchestration, verification evidence, review, QA, PR, or merge automation.

## Implementation constraints

- Treat repository task and Git output as untrusted input.
- Use argument-array subprocess execution with bounded output.
- Restrict artifacts to validated `.autocode/runs/<task-and-commit>/` paths.
- Do not overwrite artifacts whose content no longer matches the deterministic preparation output.
- Implement only from `feat/AC-003-jit-planning` in its isolated worktree.

## Done when

- [ ] A valid selected task produces commit-bound metadata, a task snapshot, and a fresh plan template.
- [ ] The plan context contains the selected task only and does not include later task content.
- [ ] Repeating preparation is idempotent; task/commit changes create distinct or rejected stale artifacts.
- [ ] Missing sections, placeholders, unsafe Git state, and artifact conflicts fail without partial success.
- [ ] Documentation and `SYSTEM.md` match behavior.
