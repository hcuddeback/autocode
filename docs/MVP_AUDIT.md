## End-to-end behavior inspected

The runner validates one ready task, the declared feature branch and linked worktree, configured commands, and task/commit preparation. Planning is read-only; implementation consumes its generated plan. Deterministic failures defer review; actionable review schedules a bounded fix with fresh check/review artifacts. Successful earlier rounds explicitly skip unused rounds. QA and completion require recorded applicability and evidence. A missing remote adapter blocks a PR-required task. Completion never writes `done`, moves task files, merges, deploys, or selects another task.

Version 18 receipts bind the complete task, configuration, operator policy, editable prepared plan, branch/base commit, phase identity, post-phase workspace digest, and resolved verification executable identities/content. Verification read files participate in receipt and live/check freshness. QA/completion also bind copied adapter configuration and executable/read-file snapshots; changes reject old evidence. Codex, verification and supplied required-QA launch resources are preflighted before durable/model effects. Shared process/Codex output is capped at 16 MiB. Explicit sandbox read resources must be exact absolute regular files; directories and links are rejected.

Windows model, verification and QA commands share AppContainer/Job containment. Protected metadata and private data are isolated before execution; ignored repository files and existing files under non-repository writable roots are private by default, with exact operator resource exceptions that cannot expose known credentials or durable evidence. Sanitized process environments omit operator tokens. Trusted-host Git inspection disables repository helpers. Protected-state and credential checks run after descendant termination, including failed processes; detected tampering terminates the run. Receipt publication does not overwrite an existing receipt. Read-only roles and QA cannot silently change the workspace and retain old check evidence. Restart validates current identity; successful current model/check receipts reconcile, while uncertain effects block. QA and completion advance only from durably completed phases, with attempt-bound recovery when an absent QA adapter prevented any callback invocation.
