## End-to-end behavior inspected

The runner validates one ready task, the declared feature branch and linked worktree, configured commands, and task/commit preparation. Planning is read-only; implementation consumes its generated plan. Deterministic failures defer review; actionable review schedules a bounded fix with fresh check/review artifacts. Successful earlier rounds explicitly skip unused rounds. QA and completion require recorded applicability and evidence. A missing remote adapter blocks a PR-required task. Completion never writes `done`, moves task files, merges, deploys, or selects another task.

Receipts bind the complete task, configuration, operator policy, editable prepared plan, branch/base commit, phase identity, and post-phase workspace digest. Protected-state and credential checks run around model callbacks. Receipt publication does not overwrite an existing receipt. Read-only roles and QA cannot silently change the workspace and retain old check evidence. Restart validates current identity; completed effects are reconciled from successful receipts while uncertain effects block.

## Remaining MVP acceptance work

1. **Settle the external lifecycle boundary.** PRODUCT still asks which PR/production phases enter MVP 1, while WORKFLOW requires the complete remote journey for PR-required tasks. That scope conflict requires an explicit product/decision update or implementation of the narrow remote adapters; a local fixture exception does not resolve it.
2. **Finish applicable QA recovery.** Add a supported CLI scenario mechanism and route QA findings through persisted bounded fixes with fresh verification, independent review, and QA. Preserve operator escalation when a result is ambiguous.
3. **Finish lifecycle ownership.** Record active task ownership durably, handle resume for that ownership, produce a final immutable summary, and perform authorized task/system updates after applicable gates. Preserve dependency readiness and do not claim `done` at local PR readiness.
4. **Prove supported platforms and live Codex compatibility.** Windows uses Job Object containment. Linux and macOS process execution fail closed; Linux user cgroups do not isolate the user manager. This leaves PRODUCT's three-platform requirement unmet until manager isolation and platform acceptance are verified. Document tested Git/Codex/Node versions and run authenticated fixture smoke with explicit source-sharing authorization.
5. **Close release/security gates.** Add CI, choose license and public package/binary identity, configure private vulnerability reporting, perform dependency audit and secret scan, and verify a distribution artifact through clean installation/upgrade, help/init, fixture/resume, and uninstall preservation. The package remains private and no production release exists.

Select each remaining outcome JIT after AC-012 merge gates; this audit does not authorize adjacent implementation on the integration branch.
